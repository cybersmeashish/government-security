# 23 — Original research: local government authority during disconnection

Ashish Srivastava · 19 November 2026 · original, unreviewed reference experiments

## Research question

Can a public-service reference preserve explicitly scoped local review while refusing expanded record, action, import and disclosure authority when central connectivity is unavailable? Which apparently valid artifacts still fail to establish freshness, durable replay protection or recovery completeness?

## Method

Run a digest-pinned Python container with external networking disabled, only loopback, non-root identity, read-only root, dropped capabilities, no-new-privileges, one CPU, 256 MiB and 64 processes. Three synthetic records represent civic and registry scopes at one logical site. Provision trusted local fixture sessions; exercise actual HTTP requests, context-bound emergency approvals, signed shared admission/update controls, a deterministic AI router, filtered export and clean encrypted restoration.

Verify 22 government runtime/test/example/recipe/lock inputs and 52 separately pinned shared source inputs. Repeat **54 government regression tests** on the host and isolated container. Record **63 isolated scenario expectations**. Test counts describe unique methods, not totals accumulated across environments.

## Findings

| Finding | Actual observation | Decision consequence |
| --- | --- | --- |
| Local review and final authority differ | Scoped read/marker allowed offline; finalization denied offline and at connected age 301 | Declare locally permitted actions and their stop conditions |
| Valid identity does not imply object/action authority | Real API cross-record/cross-agency requests returned 403; viewer action returned 403 | Enforce authorization at server object/action boundaries |
| Emergency approval needs context and freshness | Bound two-duty read allowed; retarget, duplicate, expiry and replay denied | Protect approval identity, requester/object binding and consumed state |
| Signed update validity does not establish durable freshness | Replay denied in an existing gate; old valid release accepted by a newly constructed gate | Fund protected persistent anti-rollback state |
| Central knowledge ages | Same report current at modeled time 160, delayed at 161 | Gate central conclusions on freshness, completeness and trust |
| Illustrative detection misses unfamiliar patterns | Repeated denial rule alerted; unknown import-pattern rule did not | Measure coverage rather than infer it from pipeline health |
| Disclosure authority is purpose/recipient/data specific | Operational fields filtered; wrong purpose/recipient/classification/replay denied | Separate incident review from record disclosure and model training |
| Invalid-time evidence affects completeness | One invalid-time event quarantined and its export denied | Report missing/unverified evidence rather than claim complete export |
| Recovery loss is observable | Three snapshot records restored; actual later record `permit-after-snapshot` absent | Enumerate lost changes and test approved recovery objectives |
| AI authenticity and effect authority differ | Signed router data admitted; cross-agency/shell/nonadmitted tool requests denied | Keep model-data admission separate from retrieval/tool permission |

## Measured restoration

Five tiny fixture restores had a median of **0.00030245 seconds**, with raw samples retained. Timings include approval-signature construction plus the restore call; software-key recovery was verified separately. Configuration matched and recovered software keys decrypted the retained test value. The live fixture had four records; the restored snapshot had three. Wrong wrapping material and a dirty target were rejected.

This is tmpfs fixture timing, not an agency service recovery objective or production capacity result. Identity/session/approval/replay state was not included in the snapshot.

## Unsafe gaps and uncertainty

Expected-gap scenarios: `unknown_event_detection_gap, placement_no_observation, placement_matching_claims_gap, ephemeral_update_restart_gap`. Passing these expectations records a limitation; it does not establish production-safe enforcement.

The fixture has no production login/MFA/TLS, protected durable authority/clock/replay state, HSM, independent placement evidence, provider deployment, physical air-gap validation or learned model. No real citizen data, government determination, agency adoption, national capability score, compliance conclusion or accreditation was produced. The original results have not been peer-reviewed.
