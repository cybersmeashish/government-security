# 12 — Supplier and procurement evidence pack

Ashish Srivastava · 19 November 2026 · **Procurement/acceptance reference pack**

## Procurement decision pack

Ask for evidence about the authority and lifecycle of the actual product rather than accepting a sovereignty label.

| Acceptance area | Requested supplier evidence | Reference position | Owner |
| --- | --- | --- | --- |
| Trust inputs | Approved signer/public-key/builder ownership and change process | Pinned verification inputs in a synthetic fixture | Acquisition / security |
| Disconnection | Identity, DNS/time, licensing, registry, monitoring and recovery dependencies | Shared dependency research; no provider product tested | Acquisition / operations |
| Update paths | Quarantine, signatures, subject/destination/provenance, duties and rollback | Government signed-update cases executed | Security / operations |
| Placement and support | Workload/backup/evidence/recovery location and admin/support paths | Independent evidence unresolved | Operations / records |
| State and recovery | Protected anti-rollback state, key custody, restore proof and exit process | Restart replay gap and tiny software-key restore recorded | Security / recovery |

## Acceptance process

Create a decision record naming the mission, criterion, supplied artifact, verification method, reviewer, exception and next review. Keep mandatory terms separate from scored preferences. Do not mark a criterion “passed” from marketing language or a documentation-only comparison.

The JSON pack distinguishes tested fixture criteria, reference design and unresolved deployment gates. This is not an approved federal contract clause or acquisition/legal determination.
